# План развития: «Последний рейс: Эвакуация»

Задания для Cursor (или любого разработчика). Делай этапы по порядку: каждый этап — отдельная законченная фича, которую можно опубликовать.
Перед началом прочитай `README.md` (раздел «Продолжить в Cursor») и `.cursor/rules/flycrash.mdc`.

## Главная идея

Сейчас цикл такой: прилетел в аэропорт → загрузил пассажиров под атакой зомби → долетел до острова → получил деньги → купил самолёт. Через час покупать уже нечего.

Новый цикл: **каждый спасённый — житель твоего острова**. Деньги с рейсов идут на постройки, а постройки дают бонусы для полётов. Игрок видит, как его пустой участок превращается в город. Это главный мотив возвращаться в игру.

```
рейс → спасённые + деньги → постройки на острове → бонусы (вместимость, ремонт, дальность) → рейсы сложнее и выгоднее
```

## Этап 1. Участки на острове (тайкун-база)

**Цель.** У каждого игрока на сервере свой участок на острове-убежище, на нём он строит здания. Прогресс сохраняется.

### Участки
- Остров: центр `x=4900, z=0`, верх травы `y=4`, полоса по оси Z на `x=4900`, перрон и здания на `x≈5010…5130`. Участки размещай на свободной западной половине: `x = 4600…4840`, `z = -800…800`.
- 6 участков по 220×240 studs. Сделай их в `tools/build_place.py` (новый список `plots`, модель `Workspace/Plots/Plot1..Plot6`). В каждом: плита-основание (`PlotBase`, материал Concrete, плоская, у земли — WorldBuilder сам срежет под ней траву), табличка `PlotSign` с `SurfaceGui`/`BillboardGui` для имени владельца, точки `BuildSlot1..N` (невидимые детали 1×1×1 с атрибутом `Building`, куда ставятся здания).
- Новый серверный скрипт `src/server/BaseServer.lua` (добавь в `build_place.py` рядом с остальными скриптами).
- При входе игрок получает свободный участок (атрибут `Owner` = UserId на модели участка, имя на табличке). При выходе участок очищается.

### Постройки (стартовый набор)
Таблица `BUILDINGS` в `BaseServer.lua`. У каждой постройки уровни 1–3, цена растёт ×2,5 за уровень, плюс требование по числу спасённых.

| id | Название | Цена ур.1 | Нужно спасённых | Бонус |
|---|---|---|---|---|
| `tents` | Палатки → Дома → Квартал | 200 | 0 | +2 / +5 / +10 к вместимости любого самолёта |
| `hangar` | Ангар | 500 | 20 | открывает тяжёлые самолёты (категория «Тяжёлый»: 747, Ан-225, AC-130) |
| `fuel` | Топливный склад | 400 | 30 | +25% / +50% / +100% к дальности (нужен для дальних точек, этап 2) |
| `workshop` | Мастерская | 600 | 50 | ур.1: 1 бесплатный ремонт за рейс (вместо взрыва при жёсткой посадке — повреждение); ур.2–3: больше запаса прочности |
| `hospital` | Больница | 800 | 80 | заражённые пассажиры не превращаются в полёте и платят полную цену |
| `walls` | Стены и ПВО | 1200 | 150 | орды в аэропорту приходят на 25% / 50% / 75% позже |

- Модели зданий: простые из деталей (как в `build_place.py`), по одной модели на уровень, хранить в `ServerStorage/BaseBuildings/<id>_<lvl>`. Позже их можно заменить моделями из Toolbox.
- Население участка = сумма спасённых игроком (`leaderstats.Спасено`). По участку ходят NPC-жители: 1 на каждые 10 спасённых, максимум 15 (переиспользуй код гражданских из `OutbreakServer.lua`, только без зомби).

### Интерфейс
- Кнопка **«БАЗА»** в верхнем меню (рядом с «САМОЛЁТЫ»). Открывает панель: список построек, уровень, цена, требование, кнопка «Построить / Улучшить». Стиль — как у ангара (`buildCards` в `FlyCrashClient.lua`).
- Сеть: новый RemoteEvent `Net/Base`. Клиент → сервер: `("build", id)`. Сервер → клиент: `("state", json)` со всеми уровнями и `("toast", text)`. Сервер обязан проверять деньги, требования и максимальный уровень — клиенту не доверяем.
- После постройки: звук `Coin`, всплывающая награда (`HangarEvent:FireClient(p, "reward", ...)` уже есть), камера на 2 секунды показывает новое здание.

### Связь с полётами (в `FlyCrashServer.lua`)
- Бонусы читаются через атрибуты игрока: `BaseCapacityBonus`, `BaseRangeMul`, `BaseRepairs`, `BaseHospital`, `BaseHordeDelay`. `BaseServer` их выставляет, `FlyCrashServer` только читает.
- `spawnFlight`: `f.capacity = FCCapacity + BaseCapacityBonus`.
- Покупка самолёта: если категория «Тяжёлый» и нет ангара — отказ с тостом «Нужен ангар на базе».
- Жёсткая посадка (`HARD_LANDING_VY`): если `BaseRepairs > 0` — не `crash()`, а «повреждение»: минус ремонт, сообщение «Мастерская спасла самолёт», штраф −50% к награде.
- Орды: `f.hordeAt = os.clock() + CFG.HORDE_FIRST * (1 + BaseHordeDelay)`.

### Сохранение
- DataStore `FlyCrash_v1`, ключ `p_<UserId>`: добавь поле `base = { tents = 2, hangar = 1, ... }`. Старые сохранения без `base` должны загружаться (по умолчанию все уровни 0).
- `BaseServer` и `FlyCrashServer` не должны писать один и тот же ключ одновременно: сохраняй всё через одну функцию. Проще всего — отдать `base` через BindableFunction `ServerStorage/FlyCrashAPI` (она уже есть) и сохранять в `savePlayer`.

**Готово, когда:** новый игрок получает участок; может построить палатки за $200; после рейса с острова видит свой участок с палатками и жителями; перезашёл — постройки на месте; с палатками ур.1 в Cessna садится на 2 пассажира больше.

## Этап 2. Несколько точек эвакуации

**Цель.** Не один аэропорт с пассажирами, а 3–4 точки разной сложности. Игрок выбирает, куда лететь.

| Точка | Где | Зомби | Пассажиров | Цена за пассажира | Условие |
|---|---|---|---|---|---|
| Аэропорт (сейчас) | `PassengerZone` у `x=-232` | обычно | 30 | $25 | — |
| Деревня | грунтовая полоса у одной из деревень | мало | 10 | $15 | — |
| Город | полоса у `City` | много, орды чаще | 50 | $40 | Топливный склад ур.1 |
| Военная база | далеко на западе (`x≈-4500`) | очень много | 20 военных | $80 + шанс разблокировать вертолёт | Топливный склад ур.2, Стены ур.1 |

- Каждая точка — модель `Workspace/EvacPoints/<id>` с `PassengerZone`, своей короткой полосой (`Runway`-сегмент, чтобы работали подсказки посадки и ворота глиссады) и укрытиями.
- `OutbreakServer.lua`: гражданские и зомби спавнятся по всем активным точкам (параметры из таблицы выше).
- Клиент: маркер цели и стрелка ведут к выбранной точке. Выбор — на карте в панели миссии (простой список с расстоянием и наградой).
- Дальность: у каждого самолёта топливо на `FUEL_SEC` секунд полёта, `× BaseRangeMul`. На HUD — шкала топлива. Кончилось топливо — двигатели глохнут, планируешь вниз.

**Готово, когда:** с острова можно выбрать «Деревня» и «Аэропорт»; маркер ведёт к выбранной точке; город закрыт, пока нет склада.

## Этап 3. Удержание игроков

- **Ежедневные задания** (3 штуки, обновляются раз в сутки по UTC): «Спаси 30 человек», «Сядь мягко 3 раза», «Улети, когда орда уже у трапа». Награда $200–500. Хранить в DataStore вместе с датой.
- **Ранги пилота** по числу спасённых: Стажёр (0), Второй пилот (50), Капитан (200), Командир эскадрильи (500), Легенда эвакуации (1500). Показывать над головой (BillboardGui) и в таблице игроков.
- **Глобальная таблица лидеров**: `OrderedDataStore("FlyCrash_Rescued")`, обновление раз в 2 минуты. Табло на острове возле башни (SurfaceGui на детали) — топ-10.
- **Награда за вход каждый день**: серия дней: $100, $150, $200… седьмой день — уникальная ливрея.

## Этап 4. Кооператив и события

- **Стрелок у трапа**: второй игрок в самолёте на земле может стрелять (инструмент «Ракетница» — оглушает зомби на 5 с). Пилот + стрелок получают одинаковую награду.
- **Ночные рейсы**: `Lighting.ClockTime` по таймеру сервера; ночью зомби быстрее, награда ×2, у самолётов включаются огни.
- **Заражённый на борту**: с шансом 10% один из пассажиров заражён; через 60 с полёта — паника (тряска камеры, звук `Alarm`), если не сел за 30 с — минус половина пассажиров. Больница на базе убирает эту механику.
- **Зомби на лодках** (поздно, после 300 спасённых): иногда идут к острову, их нужно отбить стенами/ПВО, иначе ломается одна постройка (чинится за деньги).

## Этап 5. Монетизация (после того как игра стабильна)

Только честные вещи, без «плати, чтобы выиграть»:
- Game Pass «Ливреи премиум» — 10 эксклюзивных раскрасок.
- Game Pass «×2 деньги».
- Developer Product «Мгновенный ремонт» / «$1000».
- Используй `MarketplaceService`; обработку покупок (`ProcessReceipt`) — строго по документации Roblox, с сохранением в DataStore до возврата `PurchaseGranted`.

## Технические правила для всех этапов

- Весь игровой расчёт — на сервере. Клиент только показывает и шлёт намерения (`build`, `fly`, `buy`).
- Новые скрипты добавляй в `src/` и подключай в `tools/build_place.py`. После правок: `python3 tools/build_place.py` → открыть `FlyCrash.rbxlx` в Studio → Play → проверить Output (строки `FlyCrash…`).
- Своё место с моделями обновляй так: `python3 tools/update_my_place.py "путь/к/месту.rbxlx"`.
- Числа (цены, бонусы) держи в таблицах `CFG` / `BUILDINGS` в начале скриптов, чтобы их было легко балансировать.
- Тексты для игроков — на русском. Не используй символы вроде ✕ ↻ ● — в шрифтах Roblox они превращаются в квадраты.
